5-minute setup
The photo wall

Let guests upload

Right now the photo wall on index.html only shows the seed photos baked into data.js. Follow these steps once and guests can tap “+ Add a photo” from their phone — every upload lands in a Google Drive folder you own and appears on the wall for everyone.

How it works (so you know what you're building) A second tiny Google Apps Script — separate from the RSVP one — runs as a public Web App. When a guest picks a photo, the page resizes it in their browser (so it's not a 20 MB monster), sends the bytes to your script, and the script saves the file into a Google Drive folder you'll create. The same script also returns the list of uploaded photos when the wall loads, so the grid stays fresh for everyone.

Why a separate script? Different responsibilities, different deploy cadence. You can break or redeploy the photo wall without touching RSVPs, and vice-versa.
One thing to know up front Photos uploaded by guests are publicly viewable to anyone with the link (that's how the wall can display them without sign-in). The folder itself is unlisted, but treat photos guests upload as "shareable to people who have the page URL." Same privacy posture as the rest of the page — keep the URL out of public posts.
1

Make a Google Drive folder for the photos

  1. Go to drive.google.com, signed in as [email protected].
  2. Click New → New folder. Name it "Fiesta Photo Wall — Emma & Jake".
  3. Open the folder. Click the folder name at the top → Share → Share. Under "General access" change Restricted to Anyone with the link, role Viewer. Click Done.
  4. Look at the URL bar. It looks like: https://drive.google.com/drive/folders/1Ab2Cd3EfGhIjKlMn... Copy the long string after /folders/ — that's the folder ID. You'll paste it into the script in Step 3.
Why "Anyone with the link"? Each uploaded photo inherits the folder's sharing setting. If the folder is private, the <img> tags on the page can't load the photos — guests would see broken tiles.
2

Create a new Apps Script project

  1. Go to script.new — this opens a fresh Apps Script project.
  2. Rename it (top-left) to "Fiesta Photo Wall".
  3. You'll see a file called Code.gs with a stub. Delete what's there.
Don't reuse the RSVP script. Make a brand-new project. They share nothing — different endpoint URL, different deploy, different code. Mixing them is a debugging nightmare later.
3

Paste this script into Code.gs

It handles uploads (doPost) and returns the current photo list (doGet). Replace FOLDER_ID at the top with the ID you copied in Step 1. 

// Emma & Jake — California Fiesta Photo Wall
// Hosted as a Google Apps Script Web App.
// POST: saves an uploaded photo into the Drive folder.
// GET:  returns a JSON list of photos already in the folder.

// PASTE YOUR DRIVE FOLDER ID HERE (from Step 1).
const FOLDER_ID = "PASTE_FOLDER_ID_HERE";

// Optional: notify the hosts when a guest uploads. Set to "" to disable.
const NOTIFY_EMAIL = "[email protected]";

// Returns the list of photos in the folder, newest first.
// The page calls this on load to populate the wall.
function doGet() {
  try {
    const folder = DriveApp.getFolderById(FOLDER_ID);
    const files = folder.getFiles();
    const photos = [];
    while (files.hasNext()) {
      const f = files.next();
      photos.push({
        id: f.getId(),
        name: f.getName(),
        // This URL renders the image inline in an <img> tag.
        src: "https://drive.google.com/thumbnail?id=" + f.getId() + "&sz=w1200",
        created: f.getDateCreated().getTime()
      });
    }
    // Newest first
    photos.sort((a, b) => b.created - a.created);

    return ContentService
      .createTextOutput(JSON.stringify({ ok: true, photos: photos }))
      .setMimeType(ContentService.MimeType.JSON);
  } catch (err) {
    return ContentService
      .createTextOutput(JSON.stringify({ ok: false, error: String(err) }))
      .setMimeType(ContentService.MimeType.JSON);
  }
}

// Accepts a base64-encoded photo from the page and writes it to Drive.
// Body shape: { filename, mimeType, dataBase64, author }
function doPost(e) {
  try {
    const data = JSON.parse(e.postData.contents);
    if (!data.dataBase64) throw new Error("Missing dataBase64");

    const folder = DriveApp.getFolderById(FOLDER_ID);
    const bytes = Utilities.base64Decode(data.dataBase64);
    const mime = data.mimeType || "image/jpeg";
    const name = sanitizeName_(data.filename || "photo.jpg", data.author);

    const blob = Utilities.newBlob(bytes, mime, name);
    const file = folder.createFile(blob);

    // Mirror the folder's sharing so the <img> tag can fetch it.
    file.setSharing(DriveApp.Access.ANYONE_WITH_LINK, DriveApp.Permission.VIEW);

    if (NOTIFY_EMAIL) notify_(data, file);

    return ContentService
      .createTextOutput(JSON.stringify({
        ok: true,
        id: file.getId(),
        url: "https://drive.google.com/thumbnail?id=" + file.getId() + "&sz=w1200"
      }))
      .setMimeType(ContentService.MimeType.JSON);
  } catch (err) {
    return ContentService
      .createTextOutput(JSON.stringify({ ok: false, error: String(err) }))
      .setMimeType(ContentService.MimeType.JSON);
  }
}

function sanitizeName_(original, author) {
  const stamp = Utilities.formatDate(new Date(), "America/Los_Angeles", "yyyyMMdd-HHmmss");
  const who = (author || "guest").replace(/[^a-zA-Z0-9_-]+/g, "_").slice(0, 30) || "guest";
  const ext = (original.match(/\.[a-zA-Z0-9]+$/) || [".jpg"])[0].toLowerCase();
  return stamp + "_" + who + ext;
}

function notify_(d, file) {
  const subject = "Photo wall — new upload" + (d.author ? " from " + d.author : "");
  const body =
    "A new photo just landed on the fiesta photo wall.\n\n" +
    "From:     " + (d.author || "(no name on file)") + "\n" +
    "File:     " + file.getName() + "\n" +
    "Open:     https://drive.google.com/file/d/" + file.getId() + "/view\n" +
    "Folder:   https://drive.google.com/drive/folders/" + FOLDER_ID + "\n\n" +
    "Received " + new Date().toLocaleString();
  MailApp.sendEmail(NOTIFY_EMAIL, subject, body);
}
  1. Replace PASTE_FOLDER_ID_HERE with the folder ID from Step 1.
  2. Hit Ctrl/Cmd + S to save.
4

Deploy it as a Web App

  1. Top right, click Deploy → New deployment.
  2. Click the gear next to "Select type" → pick Web app.
  3. Fill in:
    • Description: Fiesta Photo Wall
    • Execute as: Me (your account)
    • Who has access: Anyone — same as the RSVP one. Guests can't sign in to upload.
  4. Click Deploy.
  5. Google will ask for permission — this script touches Drive and (optionally) Gmail, so the consent screen is louder than for the RSVP script. Click through: Advanced → Go to project → Allow. You're authorizing your own script to use your own Drive.
  6. You'll get a Web app URL ending in /exec. Copy it.
Critical "Who has access" must be set to Anyone — not "Anyone with Google account". Guests upload from their phones without signing in.
5

Paste the URL into data.js

Open data.js. Near the bottom you'll see:

photoEndpointURL: "" // see Setup-PhotoWall.html

Paste your photo-wall /exec URL between the quotes:

photoEndpointURL: "https://script.google.com/macros/s/AKfy.../exec"

Save, commit, and push. The photo wall on the live site now shows the + Add a photo tile, fetches uploaded photos on load, and refreshes after each upload.

Don't mix up the two URLs. appsScriptURL = RSVPs. photoEndpointURL = photo wall. They look almost identical (same script.google.com/macros/s/…/exec shape). Pasting the wrong one into the wrong field will fail silently in confusing ways.
6

Test it end-to-end

  1. Quick sanity check: paste your photo-wall /exec URL into a browser. You should see JSON like {"ok":true,"photos":[]} (or with photos if Drive already has any). If you see an HTML error page, jump to Troubleshooting below.
  2. Open the live index.html in your browser (or on your phone).
  3. Scroll to the photo wall.
  4. Tap the bright pink + Add a photo tile.
  5. Pick or shoot a photo.
  6. Within a few seconds the tile flips to "Uploading…" and then your photo appears as the first tile after the + button.
  7. Open the Drive folder — the file should be there with a timestamped name.
  8. Reload the page. The photo should still be on the wall — that proves doGet is working.

Diagnosing problems: in the Apps Script editor, left sidebar → Executions shows every request, success or failure. If your upload fails, click the execution to see the exception.

Troubleshooting

"Couldn't upload that one" appears on the page

The upload reached the browser's fetch but didn't get a happy answer back. Check in order:

  1. FOLDER_ID is still "PASTE_FOLDER_ID_HERE". The most common Step-3 mistake. Open the script, replace it with the real ID, save, then Deploy → Manage deployments → edit → New version → Deploy (Apps Script does not auto-deploy edits).
  2. Drive folder isn't shared "Anyone with the link." The file uploads, but the page can't display it, so the optimistic render of the new tile shows a broken image. Fix the folder sharing (Step 1), then re-upload.
  3. The deployment's "Who has access" isn't Anyone. Same fix as the RSVP script — Deploy → Manage deployments → edit → set Who has access to Anyone → New version → Deploy.

The photo wall doesn't show any uploaded photos (only seeds + the + tile)

  1. Open your photo-wall /exec URL directly in a browser. You should see JSON. If you see "Sorry, unable to open the file…" — that's the same authorization/access issue covered in Setup.html's troubleshooting. Same three causes, same fix.
  2. Open the browser devtools console on index.html. A red CORS or 401 error here means the URL pasted into data.js is wrong (most often: pasted the /dev URL instead of /exec, or pasted the RSVP URL by mistake).
  3. Check the Apps Script Executions tab. If you see no doGet entries when the page loads, the page isn't reaching the script — re-check data.js and make sure you committed + pushed to GitHub Pages.

Uploads succeed on desktop but fail on a guest's iPhone

Usually a photo size issue — the page already shrinks images to ~1600px before sending, but a 4K Live Photo or HEIC can still misbehave on older Safari versions. Ask the guest to retake using "Most Compatible" in Settings → Camera → Formats, or pick a smaller photo.

A guest uploaded something you'd rather not have on the wall

Open the Drive folder, delete the file. Reload the page — it's gone. The wall is just a live listing of that folder, so Drive is your moderation tool.

If you'd rather skip uploads entirely

Leave photoEndpointURL as an empty string in data.js. The photo wall still renders with the seed photos from wallPhotos, and the + Add a photo tile shows a friendly message telling guests uploads aren't configured.
