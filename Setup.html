5-minute setup
Wire it up

Google Sheets + Email

Follow these steps once. After that, every RSVP lands in a Google Sheet and emails pattonhaus@gmail.com automatically.

What you'll need A Google account (use the one tied to pattonhaus@gmail.com so emails come from you). About 5 minutes. No coding required — you'll paste two things.
1

Make a new Google Sheet

  1. Go to sheets.new — this opens a fresh sheet.
  2. Rename it "Fiesta RSVPs — Emma & Jake" (top-left).
  3. In row 1, paste these column headers (exact order — the script depends on it):
Timestamp	Name	Phone	Additional	Arrival	Departure	Dietary	Questions

(Tabs separate the columns — pasting into A1 fills A1:H1 correctly.)

2

Open Apps Script from the Sheet

  1. In your Sheet, click Extensions → Apps Script.
  2. A new tab opens with a file called Code.gs.
  3. Delete whatever's in there. We're replacing it.
3

Paste this script into Code.gs

It writes RSVPs to the sheet and emails you the moment one arrives.

// Emma & Jake — California Fiesta RSVP receiver
// Hosted as a Google Apps Script Web App.
// Appends a row to the sheet and emails the hosts on every RSVP.

const NOTIFY_EMAIL = "pattonhaus@gmail.com";
const SHEET_NAME = "Sheet1"; // change if you renamed it

function doPost(e) {
  try {
    const data = JSON.parse(e.postData.contents);
    const sheet = SpreadsheetApp.getActive().getSheetByName(SHEET_NAME);

    sheet.appendRow([
      new Date(),
      data.name || "",
      data.phone || "",
      data.additional || 0,
      data.arrival || "",
      data.departure || "",
      data.dietary || "",
      data.questions || ""
    ]);

    sendNotification_(data);

    return ContentService
      .createTextOutput(JSON.stringify({ ok: true }))
      .setMimeType(ContentService.MimeType.JSON);
  } catch (err) {
    return ContentService
      .createTextOutput(JSON.stringify({ ok: false, error: String(err) }))
      .setMimeType(ContentService.MimeType.JSON);
  }
}

function sendNotification_(d) {
  const partySize = 1 + (Number(d.additional) || 0);
  const subject = "RSVP — " + (d.name || "Guest") +
                  " (party of " + partySize + ")";

  let body = "";
  body += "Name:       " + (d.name || "") + "\n";
  body += "Phone:      " + (d.phone || "") + "\n";
  body += "Party size: " + partySize + " (guest + " + (d.additional || 0) + ")\n";
  body += "Arriving:   " + (d.arrival || "—") + "\n";
  body += "Departing:  " + (d.departure || "—") + "\n";
  body += "Dietary:    " + (d.dietary || "—") + "\n";
  body += "Questions:  " + (d.questions || "—") + "\n";
  body += "\nReceived " + new Date().toLocaleString();
  body += "\n— Emma & Jake's Fiesta RSVP page";

  MailApp.sendEmail(NOTIFY_EMAIL, subject, body);
}

// Visit the deployed URL in a browser to confirm it's live
function doGet() {
  return ContentService.createTextOutput("Fiesta RSVP endpoint is alive.");
}
  1. Hit Ctrl/Cmd + S to save.
  2. Name the project something like "Fiesta RSVP".
4

Deploy it as a Web App

  1. Top right, click Deploy → New deployment.
  2. Click the gear next to "Select type" → pick Web app.
  3. Fill in:
    • Description: Fiesta RSVP receiver
    • Execute as: Me (your account)
    • Who has access: Anyone — this lets guests POST without signing in.
  4. Click Deploy.
  5. Google will ask you to authorize. Click through, choose your account, "Advanced → Go to project", "Allow". This is normal for scripts you write yourself.
  6. You'll get a Web app URL ending in /exec. Copy it.
Critical "Who has access" must be set to Anyone. Otherwise guests will see a Google sign-in wall when they RSVP.
5

Paste the URL into data.js

Open data.js in this project. Near the bottom, find:

appsScriptURL: "" // e.g. "https://script.google.com/macros/s/AKfy.../exec"

Paste your URL between the quotes:

appsScriptURL: "https://script.google.com/macros/s/AKfy.../exec"

Save the file. Reload index.html. RSVPs are now live.

6

Test it

Quick clarification on what the URLs do Your Apps Script /exec URL is not the RSVP page. It's a behind-the-scenes endpoint that receives form submissions and writes them to your Sheet. Visiting it directly just confirms it's alive — there's no form there.

The actual fiesta page guests see (and where the RSVP form lives) is index.html — the file in this project. That page POSTs to your /exec URL behind the scenes when someone hits "Send my RSVP".

How to test, end-to-end:

  1. Open index.html in your browser. In this project you can just click index.html in the file list at the top. (Once you host it for guests — see the next section — you'll use that public URL instead.)
  2. Scroll to the RSVP section near the bottom.
  3. Fill in a test entry with your own name and phone. Click Send my RSVP.
  4. Open your Google Sheet — a new row should appear within a few seconds.
  5. Check pattonhaus@gmail.com — an email should be waiting (also within seconds, sometimes a minute or two).

Diagnosing problems: in the Apps Script editor, left sidebar → Executions shows every POST it received, success or failure. If you submit the form and no execution appears, the page isn't reaching the script (usually because appsScriptURL in data.js wasn't saved, or the page is cached — try a hard reload). If an execution appears but failed, the error message tells you why.

Sending the link to guests

Host this index.html (and the other project files) anywhere that serves static files. A few options, easiest to most involved:

Your existing WordPress site

WordPress's media library blocks .html/.js/.jsx uploads, so you can't go through the admin. You'll upload the files around WordPress, not into it:

  1. Connect to your site via FTP/SFTP (FileZilla, Cyberduck) or your host's control-panel file manager.
  2. Navigate to the web root — usually public_html/ or www/. This is the folder containing wp-config.php and wp-content/. Don't put your fiesta folder inside wp-content/ — keep it as a sibling.
  3. Make a folder. For privacy from web crawlers, pick an unguessable name like emma-jake-2026-x7k4q9 instead of fiesta.
  4. Upload the project files into it (preserving the photos/ subfolder).
  5. Visit yoursite.com/your-folder-name/ — you should see the fiesta page.
If you get a WordPress 404 instead of your page: WordPress's .htaccess rewrite rules are hijacking the subfolder. Edit /public_html/.htaccess and add this near the top, above the # BEGIN WordPress block (replace your-folder-name with the real name): 
RewriteEngine On
RewriteRule ^your-folder-name/ - [L]

No website? Free alternatives

  • Netlify Drop — drag the unzipped project folder onto the page, get a public URL in seconds. No account needed.
  • Cloudflare Pages — similar drag-and-drop, with a free account.
  • GitHub Pages — create a public repo, upload the files, Settings → Pages → enable. URL becomes username.github.io/repo-name/. Takes ~10 minutes the first time.

Keeping the page private from search engines

The page already has noindex, nofollow meta tags built in (top of index.html). That tells Google, Bing, and other well-behaved crawlers not to index it. For extra privacy, stack:

  • Use an unguessable folder name (see WordPress step above). Crawlers can't index what they can't find — they have to follow a link from somewhere. If your URL only lives in private text messages, no crawler will ever encounter it.
  • Don't post the link publicly — no Facebook, no Twitter, no public Instagram caption, no "open" group chat. SMS, email, and DMs are fine.
  • Password-protect the folder (optional, real security). On Apache hosts (most WordPress hosts) you can add an .htaccess + .htpasswd pair to the folder, which forces a browser login before the page loads. If you want this, ask me and I'll write the files for you with a password you choose.

Editing event details later

Every detail — date, time, address, hosts' note, dress code, hotel recommendation — lives in data.js. Edit there and re-deploy your host. Guests see the new version automatically; you don't need to re-send the link.

Troubleshooting

"Sorry, unable to open the file at this time"

The most common setup error. Three causes — check in order:

Cause 1 — Wrong URL. Apps Script shows two URLs and they look almost identical:

  • The /dev URL (from "Test deployments") only works when signed in as you.
  • The /exec URL (from "Manage deployments") is the public one for guests.

Go to Deploy → Manage deployments and copy the URL that ends in /exec. That's the one for data.js and for testing.

Cause 2 — Access not set to "Anyone".

Open Deploy → Manage deployments → click the pencil icon to edit your deployment. Three things must match:

  • Version: New version — every config change requires this, or it won't take effect
  • Execute as: Me
  • Who has access: Anyone — not "Anyone with Google account" (that still requires sign-in)

Click Deploy. You'll get a fresh /exec URL — paste it back into data.js if it changed.

Cause 3 — Script not authorized yet.

In the editor, open Code.gs. From the function dropdown at the top, pick doGet and click Run. A modal appears: "Authorization required" → Review permissions → choose your account → "Advanced → Go to project → Allow".

Sanity test: paste your /exec URL into a browser. You should see:

Fiesta RSVP endpoint is alive.

If you see that, the endpoint is public and authorized. If you still see the error, one of the three causes above is still in play.

Other sanity checks

  • RSVP submits but no row appears in the Sheet. Open Apps Script → left sidebar → Executions. Every POST is logged here, including failures with the error message. Usually it's a header mismatch — see next item.
  • Sheet headers don't match. The script writes columns in this exact order: Timestamp, Name, Phone, Additional, Arrival, Departure, Dietary, Questions. If your sheet has different headers, re-paste row 1 from Step 1.
  • Emails not arriving? Check Spam. Then Executions — if the row was written but no email arrived, MailApp probably hit your daily quota (100 emails/day for free Google accounts, which is plenty for a fiesta but worth knowing).
  • Want a different notification email? Change NOTIFY_EMAIL at the top of the script, save, then Deploy → Manage deployments → New version → Deploy (or the change won't go live).
  • Changed the script and nothing updated? Apps Script doesn't auto-deploy edits. Every code change needs Manage deployments → edit → New version → Deploy.
